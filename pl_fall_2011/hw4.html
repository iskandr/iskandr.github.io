Problem 1
Arrays in most languages (excluding Fortran, Matlab, and a few others) are laid out with their last dimension stored contiguously (a n-dimensional generalization of row major order). If indexing starts from b and V is a q×r×s array with elements of type t, then the address of V(i,j,k) will be base(V) + sizeof(t) * ((i-b)*r*s + (j-b)*s + (k-b)).

Specifically, the address of V(5,10,20) will be 5000 + 4 * (4*20*50 + 9 * 50 + 19) = 22876

Scott 8.13
The representation of an ordinary record places each field at an aligned offset from the start of the record. This means that dereferencing any individual field will not cause an alignment fault. Packed records, on the other hand, store their fields at arbitrary offsets.
Passing the address of a packed record's field as a by-reference parameter might not be valid (since it would cause your program to crash).
Similarly, an element of a smaller range may be represented with fewer bytes than an element of a larger range. A function accepting a too-small range value as a by-reference parameter may write past the end of that range value's storage and corrupt other memory.
